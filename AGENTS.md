# Правила работы с семейным дневником

Перед работой прочитать `TEAM_HANDOFF.md`, `NEW_TRIPS_WORKFLOW.md` и `DESIGN_PHOTOS.md`, затем проверить `git status --short`. Исторические записи о прежних этапах не заменяют актуальные правила. Указания владельца в текущей беседе имеют приоритет.

## Новое путешествие: сначала архив Drive, затем R2

1. Сначала сохранить все выбранные полные оригиналы в `G:\My Drive\Family Travel Blog Photos`, по стандарту папок поездок, глав и имён файлов из `TEAM_HANDOFF.md`. Это основной архив для будущего переноса сайта на любое другое хранилище.
2. Проверить количество файлов, размеры, SHA-256 и синхронизацию с облаком Drive. Сохранить `photo-manifest.json` в папке поездки и соответствующий реестр в `media-manifests/<trip>.json`: относительный путь оригинала, исходное имя, глава, связь с именем на сайте и контрольная сумма. Наличие файлов на диске G: само по себе не подтверждает облачную синхронизацию.
3. Только после проверки архива изготовить из его оригиналов экранные копии до 2000 px по длинной стороне, с правильным поворотом и без увеличения маленьких изображений. Оригиналы не уменьшать и не заменять копиями.
4. Загрузить копии в Cloudflare R2 (`family-travel-photos`), проверить каждый публичный URL и соответствие байтов локальной копии. Проверка включает фото глав, обложки поездки и глав, карточки и полноэкранный просмотр.
5. Записать связь «оригинал в Drive → экранная копия → ключ R2», размеры и SHA-256 в реестры. Архив должен позволять заново изготовить и опубликовать копии без доступа к R2; одних URL или ID Drive/R2 недостаточно.
6. На готовом сайте показывать копии R2. В `data/photos/<trip>.json` не оставлять активный Drive `url`, который перекрывает R2; исторические ссылки и сведения об оригиналах сохранять в архивном реестре. Согласованные владельцем ресурсы главы допускаются отдельно.

Поручение «сделать новое путешествие» включает оба этапа без отдельного напоминания про R2. Поездка готова только после проверки архива Drive и копий R2. Если один из этапов недоступен, продолжать независимую подготовку черновика и честно назвать незавершённый этап; не выдавать его за выполненную работу и не подменять R2 ссылками Drive для публикации.

## Сохранность текста и совместная работа

- Авторский текст, подписи, опечатки и пунктуацию сохранять дословно. Фото размещать по `DESIGN_PHOTOS.md`.
- Не менять файлы чужой поездки, не отменять чужие изменения и не останавливать чужие процессы просмотра.
- Не включать `Отчеты/`, `.tmp/`, экранные копии и личный фотоархив в Git. Добавлять в коммит только проверенные пути своей задачи, без `git add .`.
- Перед завершением поездки проверить источник, состав фото, обе стадии хранения, готовые страницы и production-сборку. Проверенную работу сохранять отдельным локальным коммитом. Для публикации учитывать уже данное разрешение владельца и его область действия.
