# Данные достопримечательностей для макета

## Типы объектов и поиск (дополнение 22 октября)

У всех 531 объектов добавлены `types` и `search_terms`. Типы назначены по смыслу
объектов, а не определяются во время поиска по словам в названии. Названия,
ID, географические родители и привязки к главам сохранены.

```json
{
  "title": "Третьяковская галерея",
  "parent": "moscow",
  "types": ["museum", "gallery"],
  "search_terms": ["музей", "музеи", "музея", "музеев", "museum", "museums", "галерея", "галереи", "галерею", "галерей", "картинная галерея", "картинные галереи", "художественная галерея", "художественные галереи", "пинакотека", "искусство", "живопись", "картины", "gallery", "art"]
}
```

`data/attraction_types.json` содержит названия типов и варианты поисковых слов.
Художественные галереи включены в категорию музеев; у замка-музея допустимы оба
типа. Тип описывает объект, но не доказывает вход внутрь: обстоятельства визита
остаются в рассказе и исходном аудите. Новых посещений эта классификация не добавляет.

**Для Клода:** передать `search_terms` каждого объекта в поисковый JSON и искать
по объединению `title + search_terms`. Все слова запроса проверять в этом общем
тексте. Например, «музей Третьяковская» должно найти галерею. Фильтр страны
оставить отдельным условием. В выдаче показывать настоящее название объекта,
без приписанного слова «музей», с городом рядом. Для географических результатов
проверять собственное название города, а не дописывать в него старые дочерние
метки музеев. Иначе снова появятся два разнородных списка совпадений.

Готовые `search_terms` генерируются из явно назначенных `types`:
`node scripts/update-attraction-search-terms.cjs`. Проверка без записи:
`node scripts/update-attraction-search-terms.cjs --check`.
Новый объект обязательно получает типы; генератор откажется обрабатывать
объект без классификации или с неизвестным типом.

`node scripts/verify-attraction-types.cjs` проверяет смысловые случаи поиска,
включая Третьяковку, Альбертину, Ленбаххаус, коллекцию Барнса, Уффици и музеи
под открытым небом. Интерфейс пока не подключён: до изменения шаблона/JS
новые поисковые слова сами по себе на сайте не заработают.

Полный перечень классификации: `reviews/attraction-types-2026-10-22.md`.

## Исходные данные и связи

Подготовлены при проверке всех поездок 22 октября 2026. Интерфейс не изменён.

В главе `places` сохраняет географические и прежние предметные метки. Новое поле
`attractions` содержит ID объектов из `data/attractions.json`:

```yaml
places:
  - dublin
attractions:
  - dublin--triniti-kolledzh
```

```json
{
  "dublin--triniti-kolledzh": {
    "title": "Тринити-колледж",
    "parent": "dublin"
  }
}
```

`title` — название для указателя, без изменения авторского заголовка главы.
`parent` — существующий географический slug. Необязательное поле `place`
указывает прежний термин `places`, если он уже существовал. Например,
`sagrada-familia` использует прежнюю страницу и идентификатор. Новые предметные
метки не создают страницы taxonomy, координаты и дополнительные строки карты.

Для строки под главой нужно выбрать `Params.attractions`, получить названия из
словаря и отфильтровать по выбранному городу. Для вкладки
«Достопримечательности» — сгруппировать главы по этим ID и сортировать по `title`.
Если `parent` сам вложен в `data/place_groups.yaml`, его географическую цепочку
нужно учитывать: например, Провинстаун относится к Кейп-Коду. Самостоятельные
места, уже стоящие на карте, остаются в `places`; они не обязаны дублировать себя
в `attractions`.

Отменённые посещения не размечены как посещённые объекты. Неназванные учреждения
не объединены с известными музеями по догадке. Вид снаружи и поездка внутрь —
разные события; пример ледника Атабаска сохранён в примечаниях проверки.

Проверка: `node scripts/verify-place-attributions.cjs`. Она проверяет все связи,
покрытие каждой главы, сохранность её тела по SHA-256 и случаи отменённых визитов.
При дальнейшем редактировании текста контрольная сумма фиксированного аудита
потребует повторной сверки; это снимок проверки, а не запрет автору редактировать.

Сводка каждой поездки — `reviews/places-audit-2026-10-22.md`; точный реестр всех
глав и основания привязок — соседний JSON. Отдельные черновики, находящиеся в
других рабочих копиях и ещё не вошедшие в этот снимок, сверены отдельно локально.
